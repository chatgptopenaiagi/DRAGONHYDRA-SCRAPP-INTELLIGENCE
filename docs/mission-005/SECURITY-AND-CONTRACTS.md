# Acquisition contracts and security

`living.csv_import` owns inspectable staged drafts. Source bytes are written to a unique partial file, flushed, then atomically renamed to their SHA-256 name. Partial evidence is not automatically deleted. Validation retains physical row diagnostics and an opaque validation identity. Confirmation snapshots source, reader and mapping into the existing acquisition queue. The single worker rechecks hashes and validates before one SQLite transaction commits observations and receipt.

Schema 3 adds namespaced component state for drafts, provider configuration, budgets and HTTP cache. Original observations retain immutable update/delete triggers. Schema ownership and integrity are checked before migrations; older schema files are backed up before migration. The composite observation identity index remains in place.

`living.football_providers` contains six dedicated adapters. Each constructs documented request parameters and parses its own provider schema. `ProviderManager` controls permission, modes, rate budgets, snapshots and receipts. It uses the existing acquisition worker; it never starts a competing worker. Changing provider configuration or removing credentials cancels older operations. Offline mode prevents new outbound requests and cancels outstanding provider work.

Canonical contracts are `football.competition/1`, `football.team/1`, `football.fixture/1`, `football.result/1`, `football.event/1`, `football.standing/1`, `football.odds.quote/1` and `football.player.statistic/1`. The first beta.2 connector scope exposes competitions, selected teams, fixtures/results, standings and two providers' recorded odds. Event and player-statistic contract names reserve extension points; their collection interfaces are not yet exposed. Raw provider records or response hashes remain available. Schema validation does not establish factual correctness.

Scheduled time, reported time, collection time, calendar date and quotation time are distinct. A provider's naive local datetime is retained but not converted to an invented UTC timestamp. Imported FT cells represent regulation-time results; ET/penalty cells remain distinct. Odds remain recorded quotations, never executable offers. Statistical transforms and source comparison candidates are not observations.

The loopback server binds 127.0.0.1. Exact Host and Origin validation, cross-site rejection, one-use expiring session tickets, HttpOnly SameSite=Strict cookies, session expiration/revocation and CSRF checks cover the new operations. No persistent browser storage contains credentials. A public nonce challenge proves ownership of the dataset's launcher secret using HMAC before the launcher sends that secret to a listening service.

The DPAPI vault uses CryptProtectData/CryptUnprotectData with UI_FORBIDDEN and **without** LOCAL_MACHINE. Provider identity, slot, dataset directory and endpoint form the entropy binding. Private files inherit owner/SYSTEM ACLs. Credential API operations are authenticated and CSRF-protected; there is no credential read endpoint. See [Microsoft DPAPI documentation](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata).

Provider HTTP transport performs GET only, uses fixed documented HTTPS origins, pins a validated public DNS address, rejects redirects, bounds response size to 5 MiB, and limits requests to 20 seconds with an 8-second socket timeout. Retryable transport/5xx failures receive at most three attempts; 429 is deferred. Pagination has a ten-page atomic limit, rejecting incomplete overflow rather than silently truncating it. Conditional ETag/Last-Modified requests reuse cached JSON when the provider returns 304. Secret echoes are redacted before persistence; the original response SHA-256 is retained. Response bodies and URLs containing private query authentication never enter logs.

An explicit test-only launch flag allows exact loopback mock origins. Such operations remain labeled MOCK_PASS, normalize as SYNTHETIC, and are visibly identified in the control center. The flag grants no access to arbitrary private network hosts. Production configurations cannot enable mock origins through the dashboard.

Provider budget counters survive restart. They represent local usage only; provider account headers are recorded separately. Free-plan metadata is a dated documentation snapshot, not an entitlement guarantee. No upgrade or billing endpoint is implemented.
