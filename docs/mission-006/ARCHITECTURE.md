# Mission 006 contracts

The existing Runtime remains the composition root and one acquisition worker owns scheduled collection. SQL, Cloud, Knowledge and EvidenceTools are independent modules using versioned stored component state. The existing single loopback HTTP server retains session/CSRF protection. No secondary server is created.

Cloud Adapter implements test, run and explicit asynchronous task inspection. Provider-specific authentication and schemas are defined in cloud_adapters.py. Vault separates football and cloud namespaces; Windows DPAPI binds keys to the user, dataset and origin. Bounded transport pins a public DNS address, requires HTTPS for cloud traffic and never forwards keys across redirects. Local/mock HTTP must be explicitly loopback configured.

Cloud preview snapshots explicit record IDs and documentation evidence. It has a configuration fingerprint, expiry, single-use identity and a deliberate sharing approval. Remote results are untrusted text and are rendered with textContent. Receipts record inputs, model, actual usage and provenance without rewriting source observations. Running cloud receipts become INTERRUPTED at restart; no paid request replay occurs automatically.

SQL uses parameterized values, validated local server and owned identifiers, explicit transactions and schema ownership. SQL maintenance state is checked before opening a driver connection. Read-only tools never accept arbitrary SQL. SQL synchronization retains evidence fingerprints and separate result/odds/entity tables. Current SQLite schema 3 remains compatible with beta.2 for rollback; newer component-state scopes are ignored by the older version.

Conversation extension: Conversations persists separate session/message/turn scopes in existing SQLite component_state; no observation schema change. Two bounded worker threads handle at most five queued/running turns. Provider wire formats are explicit in conversation_protocols.py. Tool registry validates each tool schema, owner-selected conversation scope and current enable switch, and stores a receipt for execution or failure. SQL templates are predefined and parameterized. Requests for writes become owner-action records. Hardware and existing Codex attachment are separate modules. Codex executes only after an authenticated owner instruction; cloud tool calls can only stage that instruction.

The local MCP extension uses the same loopback server, a separate scoped credential and read-only contracts. It is not an authentication bypass for other HTTP routes. Conversation/credential/engineering controls retain the existing session and CSRF checks. Provider text is rendered with textContent; no HTML from a model is executed. Existing provider secret bindings remain unchanged. SQLite backups intentionally retain conversations but contain no DPAPI credential blobs.
